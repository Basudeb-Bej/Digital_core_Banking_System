# Zero Bank — Digital Core Banking System

A full-stack digital banking web application built to explore core banking workflows, account management, and transaction processing through a web-based interface.

> **Project status:** This repository is a software project for development and demonstration. Do not use it to store real customer data or process real funds without a thorough security, compliance, and production-readiness review.

## Overview

Zero Bank brings together a React-based user interface and an Express/Node.js backend backed by MongoDB. The backend exposes API routes for authentication, administration, accounts, users, and transactions.

The project is designed around common digital banking workflows, including account-opening requests, administrative approval, fund transfers, and activity tracking.

## Key Capabilities

- **Account workflows** — support for account-related operations and account-opening workflows.
- **Administrative operations** — dedicated API routes for administrative functionality and approval workflows.
- **Authentication** — authentication endpoints and supporting session/token-related dependencies.
- **Transactions** — a dedicated transaction API route for banking transaction workflows.
- **User management** — API routes for user-related operations.
- **Web interface** — React single-page application built with Vite, React Router, and Bootstrap-based UI components.
- **Database integration** — MongoDB connectivity through Mongoose.
- **Supporting services** — dependencies for email delivery, file uploads, and PDF generation are included in the backend.

Feature availability and access controls depend on the current implementation. Review the source code and configuration before relying on any feature in a production environment.

## Getting Started

### Prerequisites

Install the following before running the project locally:

- Node.js (use a current LTS release compatible with the installed dependencies)
- npm
- MongoDB instance (local or hosted)
- Git

### 1. Clone the repository

```bash
git clone https://github.com/Basudeb-Bej/Digital_core_Banking_System.git
cd Digital_core_Banking_System
```

### 2. Configure the backend

```bash
cd ZeroCode/back-end
npm install
```

Create a `.env` file in `ZeroCode/back-end/` and configure the environment variables required by the database connection and any enabled integrations. Check the backend configuration files to confirm the exact variable names and required values. **Do not commit secrets, credentials, tokens, or production connection strings.**

Start the backend:

```bash
npm start
```

The server code defaults to port `8000` unless `PORT` is configured. Database connectivity must be configured for backend features that depend on MongoDB.

### 3. Configure the frontend

Open a second terminal from the repository root:

```bash
cd ZeroCode/front-end
npm install
npm run dev
```

Vite will print the local development URL in the terminal. If the frontend needs to call the backend, verify that its API base URL and the backend CORS configuration match your local setup.

### 4. Create a production frontend build

From `ZeroCode/front-end/`:

```bash
npm run build
npm run preview
```

The production build is generated by Vite. The preview command is intended for local verification, not as a production hosting server.

## Backend API Areas

The Express application mounts route modules for these areas:

| Base path | Purpose |
| --- | --- |
| `/api/auth` | Authentication-related endpoints |
| `/api/admin` | Administrative operations |
| `/api` | Account-related operations |
| `/api/users` | User operations |
| `/api/transactions` | Transaction operations |

These are route prefixes, not a complete API specification. Refer to the route files for the available endpoints, request formats, and authorization requirements.

## Configuration and Deployment Notes

- Keep environment-specific configuration outside source control.
- Use separate development and production database credentials.
- Configure CORS to allow only the frontend origins you intend to trust.
- Use HTTPS and secure cookie/session settings in deployed environments.
- Validate and authorize every sensitive account and transaction operation on the server.
- Review logging, error handling, input validation, rate limiting, dependency updates, and secrets management before deployment.
- Test the application with non-production data before demonstrating workflows.

This project should be treated as a learning/demo application until an independent review confirms that its authentication, authorization, transaction integrity, privacy, and operational controls meet the requirements of its intended use.
